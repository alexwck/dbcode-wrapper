# 09 — Publish public source and prepare the Private Personal Release

**What to build:** Publish a cleaned Public Source Repository, then turn the accepted same-Mac app into a versioned, host-only DMG for Macs owned by the licence holder. While the repository is public, use an authenticated GitHub draft release only as a temporary private transfer and never publish that release. Keep the current-user self-signed identity, include strong integrity evidence, and document macOS `Open Anyway` without weakening Gatekeeper globally. Each new Mac obtains the exact approved unchanged DBCode and Python/Jupyter packages separately from their official sources into its own current-user profile.

**Blocked by:** 08

**Human prerequisites:** GitHub authentication; a public GitHub repository; an explicit outbound-licence choice for the original wrapper code; approval of the clean public-history approach; and access to another owned Apple-silicon Mac
